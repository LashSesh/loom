# 13 — ÖKOSYSTEM-EXPANSIONSKARTE (die nächste Stufe: vom geschlossenen System zum sich entfaltenden Paradigma)

**Auftrag:** Technologische Expansion des Paradigmas — volles Potenzial aus dem Fundament, Entfaltung eines eigenen Ökosystems. Nicht Adoption, sondern Fähigkeit. **Standort (verifiziert):** 213/213 Domänen strukturell bewiesen · Reise klickbar mit echtem Datei-Export (Byte-Identität GUI↔headless) · Kanzel denkt real durch das Gateway · erster Arbeitskörper mit echter, attribuierter Weltquelle · SCALE-2 · Ed25519 über core_root · ein Wächter über allem.

## §1 Das Expansionsprinzip

Ein Ökosystem entsteht technologisch, wenn das System fünf Eigenschaften gewinnt — jede unter den bestehenden Toren, jede mit Zeugen im einen Wächter: **selbstenthaltend** (der Container trägt alles, was er behauptet), **verbundfähig** (Arbeitskörper referenzieren Arbeitskörper über Klassen-Anker), **selbstbezüglich** (das System mined seine eigenen bewiesenen Arbeiten), **erweiterbar ohne Aufweichung** (der S14-Pfad wird benutzt, nicht nur besessen; eine SDK-Fassade öffnet das Format nach außen), **gedächtnisfähig** (destillierte Normen ausschließlich aus Geschlossenem — L9b). Reihenfolge der Ringe: E1 → E2 → (E3 ∥ E4) → E5; die Host-Leiste bleibt gesammelt.

## §2 Die fünf Expansionsringe

**E1 · Selbstenthaltung & Format-Vollreife** *(Bau: Agent — Etappe X1, unten)*
Ziel: Ein `.loom` ist der vollständige Träger seiner Behauptung. Bausteine: (a) **Artefakt-Bytes in den Container** — ARTIFACT trägt die materialisierten Bytes (bzw. CAS_BLOB-Payload) statt nur Digest-Metadaten; `loom extract` liefert die Datei byte-identisch; Re-Import aus dem Container = Re-Import aus der Datei (schließt das im Welt-Crystal-Bericht sichtbar geführte Muster-Residuum). (b) **SCALE-2-Vollmaterialisierung** — die Mappe bündelt ihre Memo-`.loom`s physisch (CAS_BLOB), Mappen-Extraktion ⇒ n gültige Einzel-Workbodies. (c) **zstd-Transportprofil** (Klassen-Digest unberührt, canonical-stored bleibt Golden-Referenz) + **blake3-Zweitprofil** (Header-deklariert). (d) **.docx-Export** hinter demselben materialize-Vertrag (format_loss sichtbar). (e) **Signatur-Registry-Vollform**: Mehrfachsignaturen im SIGNATURE-Segment (Autor/Prüfer/ReviewGate-Slot der Familie P), `loom verify-sig --all`.
Exit-Zeugen: extract==materialize-Bytes · Mappe→n valide Kinder · zstd-Container klassenidentisch zu stored · docx-Roundtrip-Klasse · Mehrfachsignatur-Kette grün/rot.

**E2 · Verbund & Skalen** *(Bau: Agent; kleine Spec-Notiz von mir zu Referenz-Semantik)*
Ziel: Arbeitskörper zitieren Arbeitskörper beweisbar. Bausteine: (a) **Cross-Workbody-Referenz** — neue Naht-Klasse `cites(core_root, unit_ref?)`: eine Zelle stützt sich auf eine Einheit eines ANDEREN zertifizierten Containers; Gate prüft Existenz+Klasse des Ziels (lokaler Klassen-Katalog, s. E4c); Residuum `unresolved_citation`. (b) **SCALE-3 „Projektraum"**: Verbund aus Mappen + Läufen + Quellen-Workbodies als ein Red(3)-Körper; MSC(2→3)-Kerntest. (c) Der **Welt-Crystal wird Zitierziel**: ein Memo `cites` den Kristall-Workbody — der erste beweisbare Wissens-Verbund.
Exit-Zeugen: cites-Gate grün/rot (fehlendes Ziel, Klassen-Mismatch) · Red(3)-Kerntest ≃ · MSC(1→2→3).

**E3 · Selbstbezug: HBM produktiv** *(Bau: Agent)*
Ziel: Das System schürft aus den eigenen bewiesenen Arbeiten. Bausteine: HBM-Lauf über Eigenmaterial (die 213 Familien-Referenz-Cubes + Seeds als Ingest) → Facets → BlueprintCandidates → Gates → **erste zertifizierte Blueprints aus realer Eigenarbeit** (z. B. „Struktur-Muster wiederkehrender Naht-Regeln über Familien"); Registry-Eintrag + Replay. BoundedOperatorSpecialization bleibt Lock-geschlossen (R-13 unangetastet).
Exit-Zeugen: HBM-End-to-End auf Eigenkorpus, Blueprint-Kristall zertifiziert, Replay klassenidentisch, Klonungs-Lock-Negativzeuge weiterhin rot.

**E4 · Erweiterbarkeit & SDK** *(Spec: ich liefere die CoreExtension-Spezifikation vorab; Bau: Agent)*
Ziel: Wachsen ohne Aufweichen, Öffnen ohne Kontrollverlust. Bausteine: (a) **Erste echte CoreExtension durch den S14-Pfad** — Kandidat „Tabellen-Zellentyp" für die Dokumentfamilie (voller Beweiszug: Antrag, Invarianten-Erhalt, Zeugen, Wächter-Eintritt); der Pfad wird damit BENUTZT bewiesen. (b) **loom-sdk**: schmale, stabile Fassade (open/inspect/verify/extract/replay) + **wasm32-Build des motorfreien Viewers** — `.loom` im Browser prüfbar, der Reader-Prinzip-Beweis wird zur Plattform-Unabhängigkeit. (c) **Lokale Klassen-Registry**: ein Verzeichnis zertifizierter core_roots als eigener `.loom`-Katalog-Workbody (Einträge: core_root, Klasse, Domäne, Signaturen, Pfad) — Grundlage für E2-cites und jedes spätere Teilen.
Exit-Zeugen: Extension-Beweispaket vollständig + alle Alt-Zeugen grün · wasm-Viewer verifiziert R1/N-Dateien im Headless-Browser-Test · Registry-Workbody selbst `Valid` und cites-auflösend.

**E5 · Gedächtnis: L9b Normic Memory** *(Spec: ICH — eigener Zyklus in Bauverfassungstiefe; Bau: danach Agent)*
Ziel: der Paradigmakern — ein Gedächtnis, das ausschließlich aus Geschlossenem besteht. Voraussetzung: E2 (Verbund) + E3 (Blueprints) liefern das Substrat. Erst Spezifikation, dann Bau — R-1b wird geöffnet, nicht umgangen.
